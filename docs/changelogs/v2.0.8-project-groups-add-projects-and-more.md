# MYPS changes since v2.0.7-fixes-to-delete-functions-and-project-visibility (not yet released)

## Shorter validation messages in the Component Cost dialog (#275)

- The year, amount, Start Date and End Date validation messages in the Component Cost dialog no longer end with "for cost entry N". For example, a missing year now reads "Please enter a valid year."
- The change applies to both the Project and Modification Component Cost dialogs, so their messages match.
- The message for an amount that exceeds the Funding Profile is unchanged.

## Admin Areas code tables are read-only except the parent link (#276)

- **Admin Areas data comes from AAMS and cannot be added or deleted here.** In Code Tables → Admin Areas, the Regions, Provinces, Cities/Municipalities, Legislative Districts and DEOs tabs no longer have Add or Delete buttons.
- **Regions is fully read-only.** The Regions tab has no actions at all, so nothing can be added, edited or deleted.
- **Only the parent link can be changed on the other four tabs.** On Provinces and DEOs you can change the Region. On Cities/Municipalities and Legislative Districts you can change the Province.
- Each tab shows a note under its title saying the data is maintained in AAMS and only the link can be changed here.
- To change a link, click the pencil on a row. Only the parent dropdown is editable, and a confirm dialog appears before the change is saved.
- Save stays disabled until you pick a different value.
- The new region or province must already exist. Otherwise the change is refused.
- Name, Code, Participant ID and Active cannot be changed. Active is still shown but can no longer be switched on or off.
- Changing a link keeps the rest of the row's stored details intact.
- Deleting a Province no longer happens without confirmation, because Delete is no longer available.

## Scope of Work and Infrastructure Types add, edit and delete correctly (#277)

- **New Scope of Work and Infrastructure Type entries are saved as Active.** They now appear in the Project Details Major Item dropdowns, such as Type of Work. Reload the project page after changing a code table to see the change.
- **Editing a row keeps its Active status.** Before, every edit switched the row to Inactive. Any row deactivated this way needs its Active toggle switched back on once.
- **You can add a Scope of Work under an existing Work Category**, such as Construction. Only an exact copy (same category, description and infrastructure types) is rejected as a duplicate.
- Leaving Min or Max blank on a new Scope of Work no longer causes an error. A Min greater than Max is rejected with a message.
- **A Scope of Work used by major items cannot be deleted.** Delete shows a message instead of an error, including when only a pending revision uses it. Editing it is still allowed.
- **Infrastructure Types keeps the Infra ID you type if it is free.** A taken ID shows an error. A blank Infra ID gets the next free number instead of a duplicate.
- Infra ID is read-only when editing an Infrastructure Type.
- **An Infrastructure Type used by major items cannot be deleted or have its code changed**, including when only a pending revision uses it. Renaming it is still allowed.

## Funding Agreement and Funding Source fixes in Code Tables (#278)

- **New Funding Agreements and Funding Sources are now active.** They appear right away in the Funding Profile dropdowns in Project Details.
- **Editing no longer deactivates the row.** Agreements and sources keep their Active status after a save.
- **Agreements and sources in use can now be edited.** You can fix a name or switch the Active toggle on an entry a project uses. Only deleting it or changing its key is blocked: the Code of an agreement, or the Organization of a source.
- **Funding Sources used by an agreement cannot be deleted.**
- Entries used by revision funding now count as in use too.
- Editing the Fin. Seg. Code of an agreement that had no Fin. Seg. Code before now saves.
- The Nature field on a Funding Source is now saved when you edit it. It no longer reverts to its old value.
- **Adding a Funding Agreement now checks the Source Org.** It must exactly match the Organization of an existing Funding Source (for example ADB). Otherwise the save is refused.
- Any agreement or source that an earlier edit made inactive stays inactive. Switch its Active toggle back on once.

## Revision code tables save edits correctly, and Documents gain a Description column (#279)

- **Only fields that save can be edited on Revision Categories, Headers and Statuses.** Categories: Category Name. Headers: Revision Name. Statuses: Name and Description. ID columns are now read-only, and the extra Active text field is gone. Use the Active toggle instead.
- **Statuses used by approvals can now be edited.** For Approval, Approved and other in-use statuses can be renamed or have their description changed. Only Delete is refused for a status in use.
- The Revision Statuses heading now reads correctly (it previously said "Revision Statuss").
- **New reasons are active when added.** They now appear in Modification and Revision right away.
- Editing a reason keeps its categories and its Active status. Before, every edit cleared its categories and made it inactive.
- Adding a reason with a revision header that does not exist shows a clear message instead of a system error.
- The Reasons table shows a single Active toggle. The conflicting Status column, which always said Active, is removed.
- **Revision Documents can be edited and deleted again.** Before, every edit and delete failed with "Invalid Code".
- Documents shows the header and category by name, for example "Adjustment (6)". These are read-only, and the extra Active text field is removed.
- **New Description column on Revision Documents.** It is shown and editable next to the second segment. Leave it blank for no description.
- A document whose header is already used by revisions can now be edited. Deleting it is still refused.
- The file naming rule for uploaded revision documents is not part of this change.

## Program Stage, Type and Status code tables: editing, Active flag and IDs fixed (#280)

- **A Program Stage, Type or Status that programs use can no longer be renamed or deleted.** The app refuses with a "currently in use" message. You can still edit its Description and change it between Active and Inactive.
- Renaming a Program Stage that programs use (for example BP) is now refused. Before, the rename went through while a harmless Description edit was refused.
- **Program Status Approved and Working can now be edited.** Before, every edit of a status in use was refused.
- Editing a Program Type whose Description was empty no longer fails.
- **New rows are Active.** Rows added in Code Tables → Programs now show as Active instead of Inactive.
- Editing a row keeps its Active setting. Before, every edit made the row Inactive.
- **IDs are generated automatically.** The NameId column no longer appears in the list, the edit row or the confirm dialogs, and the Add row has no NameId input. The app assigns the next number when you add a row.
- Program Type no longer has a Description column or input. Existing Description values are unchanged when you edit a Program Type.
- Program Stage and Program Status keep their Description column.

## Infra Management: working Roads, Road Sections and Bridges, generated IDs, sorting (#281)

- **Add, Edit and Delete work on the Roads, Road Sections and Bridges tabs.** Rows added in MYPS can now be edited and deleted. Each list refreshes right after a save and shows a confirmation message.
- **RBIA rows are view-only.** Roads, sections and bridges that come from RBIA show an **RBIA** badge (tooltip "Maintained in RBIA") instead of Edit and Delete. Add Section and Add Bridge stay available on RBIA rows, so a new section can still go under an existing road.
- **Road IDs are generated automatically.** Add Future Road asks for the Island (Luzon, Visayas or Mindanao) instead of a Road ID. The app assigns the next free ID, for example FR00001LZ, and the confirmation message shows it. Edit shows the Road ID read-only.
- **Section and Bridge IDs are generated too.** Add Road Section and Add Bridge assign FS or FB, the next free number and the parent's island code. The number skips IDs that projects already use. Edit shows the ID read-only.
- **Column headers sort the whole list**, not only the rows on screen. The sort stays when you move to the next page, and the header shows the arrow of the active sort.
- **Rows used by a project can still be corrected.** Name, classification, length and Engineering District can be edited. Only moving the row to a different road or section is blocked.
- **A road that still has sections, or a section that still has bridges, cannot be deleted.** A message explains why. Delete the sections or bridges first.
- The Classification filter on the Roads tab now works. The filter and the Classification column list only Primary, Secondary and Tertiary, so Quaternary is gone.
- The Road Sections list shows the Length and Engineering District columns, which were blank before.
- Add Section and Add Bridge from a row open as a new entry, even after an earlier Edit.
- The Bridge dialog, like the other dialogs, scrolls, so the Create Bridge and Update Bridge buttons are reachable on smaller screens.
- RBIA bridges with no carriage way width show "—" instead of only "m". The icons on the Roads, Road Sections and Bridges tabs are removed.

## Creating a program at a later stage works again and keeps the skip reason (#282)

- **Programs can be created directly at NEP-E, HGAB-I, GAA-R and TF-R.** Before this fix, saving a new program at one of these four stages in the Add Program dialog failed with an error and nothing was saved. Creating a program at the other stages is unchanged.
- **The skip reason is saved again.** When you create a program at a later stage, the Add Program dialog skips the earlier stages and asks for a reason. The program now records that it was skipped and keeps the reason you typed. Before this fix, the reason was required but then discarded.
- The skip reason is saved only when stages are actually skipped. A program created without skipping stores no reason, even if one was entered.
- Programs created between mid-July 2026 and this fix are not marked as skipped, and their skip reasons are lost. They are not corrected retroactively.

## Sign-in shows one message for unknown User ID and wrong password (#285)

- **Failed sign-in shows one generic message.** An unknown User ID and a wrong password now show the same message: "Unable to sign in. Please verify your User ID and password and try again."
- **The sign-in screen no longer reveals whether a User ID exists.** Previously, an unknown User ID showed a different message from a wrong password.
- The old unknown-User-ID message with the doubled period no longer appears.
- The message for an inactive account is unchanged.
- The message shown when the authentication service is unreachable is unchanged.
- The login history still records the specific reason for each failed sign-in.

## Component Cost column renamed to "Publishable to PCMA" (#442)

- The "Export to PCMA" column on Settings → Code Tables → Component Cost is now labelled "Publishable to PCMA".
- The add and edit confirmation dialogs use the same "Publishable to PCMA" label (previously "Export PCMA").
- The User Manual step now says to check **Publishable to PCMA**.
- Labels only. Saved values and how the setting works are unchanged.

## RBP Summary reports show data, and signatory fields are optional (#441)

- **RBP Summary reports now show data.** RBP Summary Report and RBP Summary Report with Tier now show the same program data as the RBP (Regional Budget Proposal) report. Totals match across all three reports at every level, from project up to grand total.
- **Planning Engineer, Reviewer and Approver are optional on all three RBP reports.** You can generate the RBP, RBP Summary Report and RBP Summary Report with Tier with any of these fields left blank.
- Blank signatory fields appear empty in the report's signature block. Filled-in fields appear as before.
- The RBP Summary report forms no longer mark these three fields as required and no longer block generation when they are empty. This matches the RBP report.

## Program delete messages show the program name, not its ID (#431)

- **Deleting a program confirms it by name.** The success message after you delete a program now shows the Program Name instead of the internal ID. If no name is available, the message still shows the ID.
- The Program Stage, Program Status and Program Type tables also show the name instead of the internal ID when you delete an entry.
- **Program error messages are more consistent.** Errors on program screens now show a short title, such as "Program not found", "Program ID Mismatch", "Update Failed" or "Program Revision Not Found", with a plain-language message that explains what to do.

## Optional filters on Extract PCMIOW and Extract PC reports (#429)

- **Regional Office, Category, District Engineering Office and Implementing Office are now optional on the Extract PCMIOW and Extract PC reports.** You can generate either report with any or all of these filters left blank.
- Leaving a filter blank includes all records for that filter. Selecting values still narrows the report as before.
- The required asterisks no longer appear on these four fields for the Extract PCMIOW and Extract PC reports.
- Implementing Office stays disabled until a District Engineering Office is picked, but neither field has to be filled in.
- Regional Office is still required for the RBP, AIP and RBP Summary reports.

## Code Tables show readable column headers and names instead of internal codes (#426)

- **Code Tables changes display only.** Every value stays on its row and saves as before.
- **Revisions tabs use readable headers.** Categories shows Name and Revision Group. Headers shows Name and Group No. (the number other tables refer to). Documents shows Revision Group, Category and File Name Code.
- **Revision groups show by name.** Revisions › Categories and Revisions › Reasons show the group as, for example, "Modification (1)" or "Additional Funding (10)" instead of a bare number. Search on Reasons matches the group name.
- **Admin Areas show names instead of codes.** Regions shows the Island (Luzon, Visayas, Mindanao) instead of the island code. DEOs shows the Province name (for example Abra) instead of the province code.
- **Internal numbers are hidden.** The status number on Revisions › Statuses, Category ID on Revisions › Categories, Reason ID on Revisions › Reasons and Infra ID on Major Item › Infrastructure Types no longer show.
- **Adding an Infrastructure Type no longer asks for an Infra ID.** The system assigns the next number when you save.
- Regions and DEOs no longer show the AAMS Participant ID. Provinces, Cities, Districts and DEOs show the parent's name without the code in brackets after it.
- Category ID on Form Dropdowns and the leading Id column on every table stay as they were.

## Dashboard opens on live data, with complete island cards, region tables and trend charts (#286)

- **The Dashboard now opens on Live DB.** The map, the island cards and every other section show database figures straight away. Demo Data is still one click away in the header.
- **Island-group cards always show Luzon, Visayas and Mindanao, in that order.** A group with no projects shows ₱0 instead of disappearing.
- A fourth card, "Unassigned (no island)", appears only when some projects have no island. It replaces the old "Unassigned Group" label, and the card grid now fits four cards.
- Demo Data lists its island cards in the same order.
- **The region tables beside the map list every region, as in Demo Data.** A region with no budget shows 0.00%, and a group no longer reads "No records". Totals, shares and record counts are unchanged.
- **Both trend charts now load on Live DB.** No. of Infrastructure Projects and Annual Budget & Lump Sum Itemization Trend load in about 2 seconds and no longer stay as grey "No fiscal years" placeholders.
- The Active Filter count ("8460 Regions") and the Live Audit Feed were already fixed in an earlier release. The portfolio now counts projects (for example, "9 projects") and the feed is gone. Builds older than that fix still show the old behaviour.
- For testers, the Dashboard test steps now read: open the Dashboard (it shows Live DB), pick the fiscal year in the header, then scroll to the map, the island cards or the portfolio.

## RBP, RBP Summary and RBP Summary with Tier reports now agree (#444)

- **RBP, RBP Summary and RBP Summary with Tier show the same totals.** For the same Year, Stage, Regional Office and Program(s), the project count and amount now match across all three reports, and Tier 1 plus Tier 2 equals the total.
- **RBP Summary and RBP Summary with Tier count each cost component once.** Before, amounts were doubled where a cost component had duplicate rows in migrated data.
- **RBP Summary and RBP Summary with Tier include CSSP and LP projects on the current categories.** Projects on the older CSSP and LP categories used by migrated data are still counted.
- **RBP shows the full cost of components with several work items or locations.** Before, it showed only part of the cost.
- **RBP includes projects that have no work item.** RBP Summary already counted them.
- The RBP page header shows the fiscal year, for example "FY 2024 BUDGET PROPOSAL", instead of "FY ____ BUDGET PROPOSAL".
- The Grand Total on RBP Summary shows 2 decimals instead of 4.
- The footer of RBP Summary with Tier reads "RBP Summary Report with Tier".
- **Downloaded report files use the same naming as import files.** The name shows the report, the year where the report has one, and the date and time, for example rbp_2024_20261024-201530-xxxxxxxx.pdf.
- RBP prints the details of one work item per component; details of extra work items are not printed, but amounts are correct.
- Programs that mix older and current CSSP/LP categories show two CSSP/LP sections in RBP; totals still agree.

## Developer tooling for opening pull requests from UAT issues (#443)

- Internal developer tooling only. Nothing visible changed.

## Program-level map removed from Program Detail for now (#447)

- **Program Detail no longer shows the program-level map.** The Regions panel, region-based clustering of map points and the map's PDF export are removed as well.
- The feature is withdrawn because it is not yet safe to release. On large programs it could block Program Detail for minutes, and points with a blank Region did not appear once the region filter was on.
- The map on the Project form is not part of this change and still shows a single project.
- The program-level map is planned to return once these problems are fixed.

## Batch Restore is back in Program Details and now updates the program's Total Cost (#445)

- **Batch Restore is in the Batch Actions menu on Program Details**, next to Batch Delete. It opens the restore dialog.
- **A restored project comes back at the stage it was deleted from.** The program's Total Cost is updated to include it.
- **Batch Restore never changes an Approved program or a published project.** Those projects are refused and stay deleted, the same rule as Batch Delete.
- **A project deleted at several stages gets back only its latest deleted stage.** Restoring an older stage needs another restore.
- Lump Sum projects are restored like any other project. An itemized project cannot be restored and is reported as not found.
- A project that was never deleted is reported as "Not found or not deleted". It no longer blocks the rest of the batch.
- The message names each project that was not restored and why.
- When only some projects are restored, the message is a warning, not a green success.
- Restoring no longer fails with "Program not found".
- If the page fails to reload after a successful restore, a warning appears instead of "Failed to restore", so the restore is not repeated.
- User groups that can use Batch Delete can also use Batch Restore.

## Funding Profile section heading is now singular (#451)

- The funding section heading on the Project form now reads "Funding Profile" instead of "Funding Profiles".
- The Project Modification form uses the same "Funding Profile" heading.

## Work Locations show the infrastructure type name instead of its code (#446)

- **Work Locations show the full infrastructure type name.** The heading now reads, for example, "Configure work location for Flood Control Structures" instead of "Configure work location for FCS", in both Project and Project Modification.
- The "No work target" text and the Local Infrastructure note also show the name instead of the code.
- **Delete and copy dialogs show the name too.** The Delete Work Location, delete major item and copy major item dialogs in Project and Project Modification show the infrastructure type name.
- **Deleting a road work location lists its Start/End Station and Chainage.** Before, the Delete Work Location dialog never showed these details for roads. Bridge work locations now show their bridge-specific details again.
- **Consultancy and Non-Infra items have no coordinate fields.** Their work locations show the "No Geo-Location" note instead, on both the Project and Project Modification pages.
- Project Modification no longer shows the "Other Infrastructure" panel for Consultancy and Non-Infra items.
- The Delete Work Location dialog no longer shows coordinates for Consultancy and Non-Infra items.
- Project Modification now shows the Local Infrastructure note for local infrastructure items, as the Project page already does.
- Saved values are unchanged.

## Add and remove many projects at once in Project Group Details (#453)

- **Add Projects takes a pasted list of Project IDs.** Paste up to 500 IDs separated by commas, semicolons, spaces, tabs or new lines. A live count shows how many IDs you entered, and one click adds every project it can.
- After adding, the dialog lists each ID as **Added**, **Already in this group**, **In another group (not moved)** (with that group's name) or **Not found**. One bad or already-grouped ID no longer blocks the rest.
- **Add more** clears the box so you can paste another list without closing the dialog.
- **Adding never moves a project out of another group.** A project that already belongs to a different group stays where it is and is reported as such.
- **Remove several projects at once.** Tick rows in the Projects table, or use select-all, then click **Remove selected (N)** and confirm once. You no longer type DELETE.
- The trash icon on a row opens the same confirm. Removing only takes the project out of the group; the project itself is not deleted.
- **Remove only affects projects in the group you are viewing.**
- If someone else changes the group at the same time, you see a "Try Again" message instead of the change being applied silently.
- After adding or removing, only the Projects table refreshes. Unsaved Name and Description edits stay on the page.
- Fixed: **Update** failed with a "Category: Please provide a valid text value." error for any group that had projects. It now saves.
- Fixed: clicking a Project ID showed "Project Not Available". It now opens the project's details page, or the Lump Sum page for a Lump Sum Project.

## Infrastructure import now confirms whether it worked (#458)

- **Each import shows its own message.** After running an import from the Import dialog in Infra Management, a success or error message appears for each selected import instead of the dialog closing silently.
- The RBIA import message shows how many roads, road sections and bridges were imported, for example "Infrastructure Inventory imported from RBIA: 2520 roads, 4455 road sections and 9960 bridges." The AAMS/IOMS import shows a plain success message.
- **Failed imports can be retried on their own.** If an import fails, the dialog stays open with only the failed imports still ticked, so a retry does not re-run an import that already succeeded.
- The Import dialog cannot be closed while an import is running.
- After a successful RBIA import, the tab counts and the list on screen reload so the new Roads, Road Sections and Bridges appear. The AAMS/IOMS import does not reload the list.
