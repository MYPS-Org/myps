# MYPS changes since v2.0.6-dashboard-program-type-stage-filtes

## Groundwork for database access and deployment tooling (#263)

- Internal database tooling only. Nothing visible changed.

## Program and project deletion follows one rule (#255)

- **Program can only be deleted if it has no projects.** Delete its projects first (Batch Delete in Program Details, or the Lump Sum module), then delete the program. Delete Program no longer deletes projects along with the program.
- **Approved programs cannot be deleted**, and neither can programs that have progressed beyond their initial stage.
- The Program list disables the Delete button when a program cannot be deleted and shows the reason on hover, for example how many projects must be deleted first.
- **Batch Delete shows a preview before you confirm.** The confirm dialog lists which projects will be deleted permanently, which are deleted at their current stage, which are refused (with the reason) and which were not found. The confirm button is disabled when nothing can be deleted.
- A project still at its first stage is deleted permanently. A project that has progressed further is deleted at its current stage and can be restored.
- **Published projects cannot be deleted.** Batch Delete also refuses Lump Sum projects, which are deleted from the Lump Sum module.
- Projects in an Approved program cannot be deleted, except Lump Sum itemized projects, so import mistakes can still be corrected.
- Refused deletes now show a plain reason. Lump Sum deletes say "Program Approved" when that is the cause.
- Projects that were already deleted no longer block deleting their program.
- Some leftover project records cannot be removed automatically. The delete is refused with a message that an administrator must clean them up.
- When another delete in the same program is in progress, a delete waits its turn. If it waits too long, the app asks you to try again.
- Every permanent delete, soft delete and restore is recorded in the audit log.

## Projects list paging no longer times out (#266)

- **Paging through the Projects list no longer times out.** Before this change, page 1 loaded, but **Next** and jumping to a page number could wait about 90 seconds and then fail with a pagination error. Once that happened, every unrestricted user (for example AUC and Admin) was affected until the problem cleared itself.
- **Next**, **Previous** and page-number navigation on the Projects list now load in about the same time as page 1.
- The projects tab in **Program Details** gets the same fix, so paging through a program's projects stays fast.
- Paging in the component targets panel on a project works the same way as on the other lists.
- Filtered paging (by Program ID or Project ID), the total count and the rows shown on each page are unchanged.
- The Programs list and the other paged lists (Lump Sum, Revision, Project Groups, Reports) page as before.
- If a page ever does time out, the error is now recorded in the system log with an error ID that support can trace.

## DPC and RPC users see only projects in their DEO or region (#267)

- **DPC users see only their own DEO's projects.** The Projects list, the projects listed in a program, and the project details page show only project stages whose DEO is the user's assigned office.
- **RPC users see only their region's projects.** They see project stages whose DEO sits under the region set as their assigned office.
- **AUC and DPD Admin users see every project.** This applies even if the user is also in DPC or RPC. Users outside these four groups see the same projects as before.
- **Visibility is decided per stage.** A stage's DEO comes from its latest fully approved modification, or from the stage itself if there is none. A project appears in the Projects list when any of its stages is visible, and its stage panel shows only the visible stages.
- Lump Sum parent projects never appear for DPC and RPC users. Itemized projects follow the same DEO rule as other projects.
- **A DPC or RPC user's office must match their group.** A DPC user needs a DEO as their office, and an RPC user needs a region. If the office is blank or does not fit, the user sees no projects and gets a "No Project Access" message. Check and correct user offices before release.
- Opening a project the user may not view now shows a "Project Not Available" panel with a link back to Projects, instead of a blank page.
- **Lump Sum and Code Tables are hidden for DPC and RPC users.** They no longer appear in the sidebar unless the user is also in AUC or DPD Admin.
- This change restricts viewing only. Saving, revisions, Dashboard and Reports are not restricted yet. Dashboard links to projects outside the user's scope open the "Project Not Available" panel.
- An RPC user's region comes from the office hierarchy. For example, BARMM RPC users do not see Cotabato City or Isabela City DEO projects, because those DEOs fall under Regions XII and IX.
- The Projects list loads more slowly for DPC and RPC users. A fix is planned separately.

## Lump Sum Sub-Category dropdown shows full Thrust Description (#269)

- **The Sub-Category dropdown on the Lump Sum form now shows the full Thrust Description.** This is the same label used on the Project and Modification forms and in the Excel import and export, and it replaces the shorter, less distinct name shown before.
- Saved Sub-Category values are unchanged. Existing Lump Sum records keep the same Sub-Category.
- Two pairs of Sub-Category options still show the same label. Telling them apart is planned as a separate change.

## Page navigation works on the RBIA Roads, Road Sections and Bridges lists (#272)

- **Paging through RBIA lists works again.** On the Roads, Road Sections and Bridges lists, clicking a page number, Next, Previous, First or Last now shows that page. Before, every click showed page 1 again.
- The three lists now use the same pagination bar as other lists in the app.
- After you delete a row, the list reloads from page 1 with your current filters. This also works when the deleted row was the last one on the last page.

## Deleted projects no longer reappear when a program advances to the next stage (#274)

- **A project deleted at the current stage is not carried into the next stage.** Before, a project deleted at NEP could reappear at NEP-E under its old BP Project ID when the program advanced.
- **A deleted project stays out of every later stage.** It no longer returns two or more advances after it was deleted.
- **A program whose projects were all deleted at the current stage can now advance.** It moves to the next stage with no projects instead of showing an error.
- Advancing a program no longer runs at the same time as a Batch Delete or restore on that same program.
- Programs that already advanced with this problem still show the extra project at the later stage. This change does not remove it.
