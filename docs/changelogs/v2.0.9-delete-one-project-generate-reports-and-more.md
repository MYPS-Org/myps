# MYPS changes since v2.0.8-project-groups-add-projects-and-more (not yet released)

## Infra Management: new IDs reuse free numbers, a bridge must start on its road section, and Import is for PS Admin (S06-TC003-P001, TC010-P001, TC015, TC016)

- **New Road, Section Road and Bridge IDs take the lowest free number.** Before, MYPS took the highest number in use plus one. The IDs migrated from RBIA were assigned by hand and already run as high as FS97844 and FB97614, so only about 2,000 numbers were left, and the number of a deleted road, section or bridge was never used again. Now the unused numbers are filled first, and a deleted item's number is used again. A section or bridge number that a project refers to is never reused.
- **A bridge's From Chainage must lie on its road section.** Add Bridge and Edit Bridge refuse a From Chainage beyond the section's Length, for example "From Chainage must be between 0 and 520 m, the length of road section FS00016LZ." The bridge itself may run past the end of the section.
- **A road section cannot be made shorter than where one of its bridges starts.** For example: "A bridge on this road section starts at 500 m, so its Length cannot be less than 500 m."
- **From Chainage is in meters.** The bridge dialog labelled it in kilometres. The section list in that dialog and the Delete Bridge and Delete Road Section dialogs also said km. All of them now say meters, as the lists do.
- **District and regional users (DPC and RPC) no longer see the Import button.** The RBIA, AAMS and IOMS imports are for PS Admin. They run in the GIS service, so the button is the only place MYPS can limit them.
- Each import still reports its own result when it finishes, and the RBIA import names how many roads, road sections and bridges came in.

## Project Groups: saves are confirmed, and the saved name is what you see (S05-TC002, TC003, TC004)

- **Update on Project Group Details now says it saved.** The message "Project Group '<name>' updated successfully." appears. Before, nothing was shown, so there was no sign that the change had been saved.
- **Add Project Group confirms the save too**, with "Project Group '<name>' added successfully.", and then opens the new group's details page.
- **The Name and Description are shown as they were saved**, without spaces before or after them, and the Add Projects and Remove dialogs show that saved name.
- **A name that a deleted project group had is refused with a message that says so:** "A deleted Project Group already used this name. Please enter a different name." Before, it said "Project Group Name already exists." even though no such group is in the list. The name of a deleted group still cannot be used again.
- If you open another project group while the details page is still loading, the page now shows the group you opened last.

## Modification: a revision with a blank Component Cost date can be submitted, and a year added on Re-Submit keeps its Year (S02-TC003-P001)

- **Submit Revision Request and Re-Submit Revision now work when a Component Cost year row has no Start Date or End Date.** Since the dates became optional, such a row made the request fail with an error. The same happened before for a project whose dates were blank to begin with, for example one brought in by Import.
- **A Component Cost year row added before Re-Submit Revision now keeps its Year.** Before, the row was saved without its Year.

## Component Cost: Start and End Dates are optional, and an End Date can run into the following year (#2)

- **Start Date and End Date are no longer required.** A year row in the Component Cost dialog can now be saved with either date, or both, left blank, for when the implementation schedule is not set yet. Before, Save stopped with "Please select a Start Date." or "Please select an End Date." This applies on the project page and in Modification.
- **Each year row's End Date can run up to December 31 of the following year**, because the funds stay valid for two years. For example, a 2029 row can end as late as December 31, 2030. Before, the End Date had to be in the row's own year. The Start Date still has to be in the row's year.
- **Date and Year problems now show as a message at the top right when you click Save**, on the project page and in Modification, for example "End Date must be between 01/01/2029 and 12/31/2030." Before, the browser showed its own pop-up under the field ("Value must be ... or earlier."). A date that is entered is still checked: the Start Date must be in the row's year, the End Date cannot be before the Start Date, and the Year must be within the program's years.
- Not fixed yet: **Auto-fill** of the component Description for Local Infra. The description comes from the GIS service, which is outside this release.

## Code Tables: a refused save shows only its reason, and the revision form names its Reason (S04)

- **When Code Tables refuses a save, you now see one message: the reason.** Before, a second message followed it. For example, adding a Category whose amount range overlaps an active one showed "The range … overlaps with active category …" and then "Failed to add category.", which read as if something else had gone wrong. This applies to every Code Tables screen: add, edit, delete and Active / Inactive.
- The general "Failed to …" message still appears when the server cannot be reached or gives no reason.
- **The revision form's header shows the Reason by name.** Before, it read "Modification Reason: 12", the reason's number. It now reads, for example, "Modification Reason: Altered Site Conditions".

## Code Tables: Validation Dates are saved and set when revisions can be requested (S04-TC016)

- **Validation Dates are now saved.** Before, the screen showed sample rows for 2016 to 2024, and Add, Edit and Delete only changed the page: a reload brought the samples back.
- **A new revision request is accepted only inside its funding year's window.** For a project whose program year has an active range, Request Revision outside the dates is refused with *"Revisions of FY \<year\> projects can be requested from \<start\> to \<end\>."* A year with no range, or an Inactive one, has no limit. A request returned For Correction can still be resubmitted.
- One range per funding year; the Start Date cannot be after the End Date. The **Window** column shows **Open**, **Not open yet** or **Closed**.
- The list starts empty: the old sample rows were placeholders. PS Admin enters the real ranges.
- Internal: the database needs `Migration.RevisionValidationDates.2026-10-30.sql` once per environment. Until it runs, the screen shows no ranges and nothing is enforced.

## Code Tables: edits no longer switch rows off, and rows in use are protected (S04)

- **Editing a Revision Rule or an Origin no longer makes it Inactive.** Before, a rule edited on the **Rules** screen was switched off and disappeared from the list, and its revisions could no longer find their editable fields; an edited Origin disappeared from Add Project. A new Origin is now created Active too.
- **Every changed field is in the history.** An edit that changed two fields used to record only the last one, and Sub-Category (Thrust) changes were recorded under Category.
- **Deletes and changes that would break saved data are refused, with the reason:** a Revision Header, Category, Reason or Rule still in use; moving a Reason used by requests to another header (those requests then failed with "Revision Reason not found"); a Cost Type projects use (it used to fail with a generic database error); an Infrastructure Type a Type of Work lists; removing an Infrastructure Type from a Type of Work that Major Items use with it; changing the source organization of a Funding Agreement in use (its funding lines showed a blank Agreement).
- **Program Stages can no longer be added.** A stage added here could not be used: a program at it could not be opened. Edit a stage's Description or set it Inactive.
- **Adding a Type of Work asks for its Target Unit and a Max.** Before, it was saved with Target Unit "0" (the form showed "Physical Target (0)"), and a blank Max became a limit of 0.
- **Checks on save:** a Sub-Category (Thrust) needs a PAP Key and a description, and its Valid From cannot be after its Valid To; a Category needs a name, and its Min Amount cannot be above its Max Amount; an Origin needs a name.
- The Sub-Category PAP Key, the Agency NameId and a Rule's Reason are shown read-only when editing: changes to them were never saved.
- Setting a Funding Source Active or Inactive no longer changes a blank Nature to Local, and two people adding to the same table at once no longer get the same Id.
- In a Modification, choosing another Type of Work for a Major Item whose Infrastructure Type has since been set Inactive is accepted; it was refused with an error about the Infrastructure Type.
- Internal: two exception-report endpoints in Program Details built their query from the Program ID as text; they now pass it as a parameter.

## User Management: older accounts can be edited, lists page correctly, and no one can lock themselves out (S04)

- **Edit User saves for older accounts.** Accounts saved without an Employee ID, or whose office has no region on record, could not be saved: Save was refused with "Employee ID is required" or "Invalid Region Code". They now save, and the region already on record is kept.
- **Edit User says when a user has no Employee ID on record** (S04-TC028), and how to add it: enter the Employee ID and click the search button to fill in the details from PIS. View User shows "Not recorded" for such a user.
- **The Users, User Groups and App Modules lists page correctly.** Page 2 and later used to show page 1 again. The lists now reload after Add, Edit or Delete.
- **Deleting a user you just added deletes that user.** Before, a newly added user was given another user's number until the page was reloaded, so its Delete removed someone else. Delete is now also refused if the user shown is not the one on record. The same applied to a newly added App Module.
- **The User Group filter matches the group exactly** (S04-TC027). Filtering by "Admin" no longer also lists the members of "DPD Admin".
- **You cannot lock yourself out.** Your own account cannot be set Inactive or have its groups changed, and your own group cannot lose its User Management access. Ask another administrator.
- **Add User needs an Employee ID, and two users cannot share one.** Changing the Employee ID after a search now clears the details found, so a user is never added under someone else's Employee ID.
- **The DPC, RPC, AUC and DPD Admin groups cannot be renamed.** What their members see depends on these names.
- **Filter Group by Permission Name works** (S04-TC029). It was ignored, so the full list came back. It now lists the groups granted a permission whose module, controller, action or page name contains the text, and Clear Filters works when only Permission Name is filled.
- The Add and Edit Group dialogs explain Apply Filter: a user in several groups is region-filtered only when all their groups have it on. Delete Group no longer shows its error message twice.
- **Security:** the PIS employee lookup and the raw projects export could be called without signing in. They now need a signed-in user: the lookup needs User Management access, and the export only covers programs the user can open.

## Users limited to their region see only their region in search, Project Groups and Import (S04-TC031)

- **Global Search** no longer returns other regions' projects or programs to a user whose groups have Apply Filter, or to a DPC or RPC user outside their offices. Before, searching by Project ID, Alternate ID, Description, UACS or Program Name listed them, even though opening them was refused.
- **Project Groups:** such a user cannot find another region's project to add to a group, and filtering the groups by its Project ID finds nothing. A group's details and its count in the list show only the projects they can open.
- **Import, Update and Export** of another region's program are refused with "Access Denied". Before, they were accepted when the Program ID was sent to the server directly. The same applies to the server's program search, which the screens do not use.
- Users whose groups don't have Apply Filter, such as administrators and AUC, see everything as before.

## Code Tables: setting a value Inactive no longer blocks the projects that use it (S04-TC001, TC002, TC007)

- **An Inactive Infrastructure Type or Type of Work no longer locks a project.** Before, once one was set Inactive in Code Tables, every save of a project that used it was refused, and its Type of Work and Unit showed blank. Now the Major Item keeps showing it and the project saves. It is only left out of the list for new Major Items, and a component whose Major Item uses it can still be deleted.
- **The same for a Funding Agreement or Funding Source:** a funding line that already uses it keeps showing it and saves. It is not offered for a new funding line, and a new Lump Sum cannot use it.
- **An Origin or Agency can be set Inactive even while projects use it.** Before, Code Tables refused with "In Use". Those projects keep showing and saving it; it is not offered when you change a project's Agency.
- **A Category or Sub-Category (Thrust) can be set Inactive while in use**, and a project whose Category is no longer valid still saves as long as its Category is unchanged. A Category or Thrust in use still cannot be renamed.
- **Category and Sub-Category validity now follows the program's year, not today's date.** A project in a 2028 program is offered the Categories and Sub-Categories valid in 2028.

## User Manual: sign-in error message brought up to date (S01-TC001-P002)

- User Manual only. The app is unchanged.
- The Login section and the message tables now quote the message the app shows when a sign-in fails: "Unable to sign in. Please verify your User ID and password and try again." They still quoted the older "Invalid credentials" message.

## Changelogs show the newest change first

- **Within a release, the newest change is now at the top.** Before, a release listed its changes oldest first, so the latest ones sat at the bottom of a long list.
- Quoted messages in *italics* and names such as Restore into &lt;stage&gt; now show as written. Before, they showed with their asterisks, or as `&lt;stage&gt;`.

## Program cost and project counts leave deleted projects out

- **A deleted project no longer counts toward its program's Cost.** Before, a project deleted at a stage after BP (one that can be restored) kept its cost in the program. Program Details and the Program list showed the old Cost until the project was permanently deleted, which past BP never happens. The Cost now drops as soon as the project is deleted, and goes back up when it is restored.
- **No. of Projects in the Program list and the Projects column of its stage rows no longer count deleted projects.** They now match the Projects table in Program Details.
- **Some older programs showed a different Cost in Program Details than in the Program list.** Their stages had been recorded out of order. When the program cost was updated, it updated an earlier stage instead of the current one. It now always updates the current stage, so Program Details shows the same Cost as the Program list.
- Internal: the database needs `Migration.ProgramCostExcludesDeleted.2026-10-29.sql` once per environment. It also updates the Cost of the programs this changes.

## Restore a project deleted at an earlier stage into the current stage

- **A project deleted before the program moved on stays deleted.** Proceeding to the next stage does not bring it back.
- **Deleted projects now also lists projects deleted at an earlier stage**, in their own section, with the stage each one was deleted at. A note explains that the program has moved on: restoring adds the project to the stage the program is at now, with the data it had when it was deleted, and the stages in between are skipped. For example, a project deleted at HGAB is restored into GAA.
- Click **Restore into &lt;stage&gt;** on a row, or tick several and click **Restore selected**. The project is back in the Projects table, and the program cost is updated. A BP Project ID becomes P, as it does when a program proceeds from BP.
- A project cannot be restored this way when it is published, when the program is Approved, when it is a Lump Sum project, or when its Project ID is now used by another project. The row says why.
- Batch Restore still restores projects deleted at the current stage, and its dialog now points to **Deleted projects** for the others.

## Permanent delete only at BP or RBP, and a Deleted projects list to restore from (S01-TC004-P002)

- **A project is permanently deleted only while it is still at the BP or RBP stage.** At any other stage, Delete and Batch Delete remove it from that stage only, and it can be restored. This now also covers a project added directly at a later stage (for example at NEP or GAA), which used to be deleted permanently.
- **A program can be deleted only while it is at BP or RBP.** A program that has moved on, or was created at a later stage, cannot be permanently deleted; the Delete button says why.
- **New Deleted projects (N) button in Program Details.** It lists the projects deleted at the program's current stage, with who deleted each one and when. Click **Restore** on a row, or tick several and click **Restore selected**, and they are back in the Projects table. You no longer need to type Project IDs into Batch Restore.
- **The delete message says only what happened.** A restorable delete reads *"1 project(s) deleted at the current stage; they can be restored from Deleted projects."* instead of starting with *"0 project(s) permanently deleted"*.
- **Project IDs are reused.** When a project is permanently deleted at BP or RBP, its Project ID is given to the next new project of the same kind. IDs starting with MY, and Lump Sum itemized projects, are not reused.
- Internal: the database needs `Migration.DeleteRulesAndProjectIdReuse.2026-10-29.sql` once per environment, for the ID reuse and the Deleted projects and Restore into stage permissions.

## Online test site signs in with its own test passwords

- **The online test site (myps.tryasp.net) signs in a few test accounts with passwords of its own.** It never contacts DPWH's PIS, so your PIS password does not work there. Ask the MYPS team for a test account.

## Delete one project from its row in Program Details (S01-TC004-P002)

- **Each project row in Program Details has a Delete button** (red trash icon) in a new Actions column. You no longer have to type the Project ID into Batch Delete to remove one project.
- It follows the Batch Delete rules. The **Delete Project** dialog first shows whether the project will be deleted permanently (still at the BP or RBP stage), deleted at the current stage (it can be restored from **Deleted projects**), or not deleted and why.
- Type DELETE and click **Yes, Delete Project** to confirm, or Cancel to stop.
- After a delete, the project table reloads on page 1.

## Generate Reports opens the Reports page for the program (S01-TC015-P001)

- **Actions → Generate Reports in Program Details now opens the Reports page** with Year, Program Stage and the program already selected. Pick the Report Type and Regional Office, then click Generate Report.
- The old report dialog inside Program Details is removed. Reports are generated only in the Reports module, where they are queued and downloaded when ready.
- A program is listed in Reports only at its current stage. Opened from an earlier stage, the program is not ticked, so choose its current stage.
- Generate Reports appears only for users who can open the Reports module.
- The RDIP and RBP Components reports from the old dialog are not in the Reports module yet.

## Changelogs button in the top bar

- **A Changelogs button sits at the top right of every page**, next to Search. It opens the list of changes in each release, newest first.
- A dot on the button marks changes you have not opened yet. It clears once you open the Changelogs.

## Dashboard header filters stay in place while the page loads (#470)

- **Program Type and Current Stages no longer move.** The header controls keep their position while the stage line, categories and fiscal years load, and after you pick a stage. Before, they slid sideways and up and down on every load.

## Funding Profile Amount reads a typed or pasted amount as pesos (#469)

- **A pasted or typed Amount keeps its value.** "1000000", "1,000,000" and "₱1,000,000.00" all read as ₱1,000,000.00. Before, the last two digits were read as centavos, so a pasted 1000000 became ₱10,000.00.
- The amount is formatted when you leave the field, not on every keystroke. Clicking into the field selects it, so a new amount replaces the old one.
- This applies to the Funding Profile on both the Project and Project Modification forms.

## Changing a component's type saves correctly (#468)

- **Changing a component's Component Type now saves.** For example, a Consultancy component changed to Civil Works becomes CW2 and keeps its year amounts. Before, saving failed with "Unable to locate Component 'CoS' for Cost Per Year." or the change was lost.
- The component's Major Items and work locations follow its new Component ID.
- Project Modification gets the same fix. Before, the edit was dropped and the component stayed as it was.

## Select Infrastructure finds Road Sections by Section ID (#466)

- **Search by Section ID or Road Name.** In Work Locations → Select Infrastructure, a Section ID such as S04516LZ now finds its road section. Before, only the Road Name matched.
- Bridges can be found by Bridge ID or Bridge Name.
- The search boxes say so: "Search by Section ID or Road Name..." and "Search by Bridge ID or Bridge Name...".

## Component Cost: clearer message when no year is entered (#465)

- "Please add at least one per-year cost." now reads "Component details are required for at least one year."
- The change applies to the Project, Project Modification and Lump Sum Component Cost dialogs.

## Batch action prompts name the program and its current stage (#459)

- **A batch action started from an older stage says so by name.** Batch Delete, Batch Restore, Allow Publishing and Restrict Publishing opened from a stage the program has moved past now show, for example, "Program 'GAA-Revisions 2026' has moved on to the GAA-R stage. Batch actions only work on a program's current stage: open it at GAA-R and try again." Before, the message said the Program ID did not exist.
- Nothing is changed when this message appears.
- Other program messages about stage, access or revisions name the program instead of its internal Program ID.
- The success message after deleting a program no longer falls back to the internal ID.

## Category and Thrust code tables filter by validity and status (#457)

- **New Validity and Status filters** sit next to Search on the Category and Thrust tables. Validity is All, Valid or Not Valid. Status is All, Active or Inactive.
- "Valid" means the row's end year has not passed. It is the same rule the Project Details Category and Sub-Category dropdowns use, so the filter shows what the project form offers.
- A Category with Valid Until 0 now reads "No expiry", like "Present" on the Thrust table.
- The User Manual explains that the project dropdowns follow validity only, and that Active or Inactive matters only once a row has expired.

## Agency and Thrust code tables are readable, and Thrust picks its Infra Type from a list (#456)

- **Agency and Thrust columns show their full text.** Long names, descriptions, programs and activities wrap instead of being cut off, so you no longer need to open Edit to read them.
- **Thrust's Infra Type is now a dropdown** of the active Infrastructure Types. A saved value that is not in the list is kept and marked "(not in list)", so editing never clears it.
- Add and edit rows on both tables use the same field height, and text fields stop at the length the database accepts.
- **Editing an Agency or Thrust keeps it Active.** Before, every edit made the row Inactive.

## User Manual: Infra Management section brought up to date (#455)

- User Manual only. The app is unchanged.
- Section 5.9 now describes Infra Management as it works today: RBIA rows show an RBIA badge instead of Edit and Delete, Classification lists only Primary, Secondary and Tertiary, and Road, Section and Bridge IDs are generated by the app.
- The Bridges column and dialog are described as Carriageway Width (m).

## Major Items of Work title no longer repeats (#454)

- The Major Items of Work section on the Project form no longer shows a second "Major Item of Work" title inside it. The Add Major Item button stays on the right.
- Project Modification gets the same change.
