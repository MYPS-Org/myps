# MYPS changes since v2.0.8-project-groups-add-projects-and-more (not yet released)

## Changelogs show the newest change first

- **Within a release, the newest change is now at the top.** Before, a release listed its changes oldest first, so the latest ones sat at the bottom of a long list.
- Quoted messages in *italics* and names such as Restore into &lt;stage&gt; now show as written. Before, they showed with their asterisks, or as `&lt;stage&gt;`.

## Program cost and project counts leave deleted projects out

- **A deleted project no longer counts toward its program's Cost.** Before, a project deleted at a stage after BP (one that can be restored) kept its cost in the program. Program Details and the Program list showed the old Cost until the project was permanently deleted, which past BP never happens. The Cost now drops as soon as the project is deleted, and goes back up when it is restored.
- **No. of Projects in the Program list and the Projects column of its stage rows no longer count deleted projects.** They now match the Projects table in Program Details.
- **Some older programs showed a different Cost in Program Details than in the Program list.** Their stages had been recorded out of order. When the program cost was updated, it updated an earlier stage instead of the current one. It now always updates the current stage, so Program Details shows the same Cost as the Program list.
- Internal: the database needs `Migration.ProgramCostExcludesDeleted.2026-10-29.sql` once per environment. It also updates the Cost of the programs this changes.

## Restore a project deleted at an earlier stage into the current stage

- **A project deleted before the program moved on stays deleted.** Proceeding to the next stage does not bring it back.
- **Deleted projects now also lists projects deleted at an earlier stage**, in their own section, with the stage each one was deleted at. A note explains that the program has moved on: restoring adds the project to the stage the program is at now, with the data it had when it was deleted, and the stages in between are skipped. For example, a project deleted at HGAB is restored into GAA.
- Click **Restore into &lt;stage&gt;** on a row, or tick several and click **Restore selected**. The project is back in the Projects table, and the program cost is updated. A BP Project ID becomes P, as it does when a program proceeds from BP.
- A project cannot be restored this way when it is published, when the program is Approved, when it is a Lump Sum project, or when its Project ID is now used by another project. The row says why.
- Batch Restore still restores projects deleted at the current stage, and its dialog now points to **Deleted projects** for the others.

## Permanent delete only at BP or RBP, and a Deleted projects list to restore from (S01-TC004-P002)

- **A project is permanently deleted only while it is still at the BP or RBP stage.** At any other stage, Delete and Batch Delete remove it from that stage only, and it can be restored. This now also covers a project added directly at a later stage (for example at NEP or GAA), which used to be deleted permanently.
- **A program can be deleted only while it is at BP or RBP.** A program that has moved on, or was created at a later stage, cannot be permanently deleted; the Delete button says why.
- **New Deleted projects (N) button in Program Details.** It lists the projects deleted at the program's current stage, with who deleted each one and when. Click **Restore** on a row, or tick several and click **Restore selected**, and they are back in the Projects table. You no longer need to type Project IDs into Batch Restore.
- **The delete message says only what happened.** A restorable delete reads *"1 project(s) deleted at the current stage; they can be restored from Deleted projects."* instead of starting with *"0 project(s) permanently deleted"*.
- **Project IDs are reused.** When a project is permanently deleted at BP or RBP, its Project ID is given to the next new project of the same kind. IDs starting with MY, and Lump Sum itemized projects, are not reused.
- Internal: the database needs `Migration.DeleteRulesAndProjectIdReuse.2026-10-29.sql` once per environment, for the ID reuse and the Deleted projects and Restore into stage permissions.

## Release notes drafted automatically when code is committed

- Internal developer tooling only. Nothing visible changed.

## Online test site signs in with its own test passwords

- **The online test site (myps.tryasp.net) signs in a few test accounts with passwords of its own.** It never contacts DPWH's PIS, so your PIS password does not work there. Ask the MYPS team for a test account.
- On that site, searching PIS for a new user in User Management shows "Employee lookup from PIS is turned off on this server."
- Nothing changes on the DPWH servers: sign-in still checks your PIS password.
- Internal: the online test site no longer fails to start on its 32-bit server, and it logs startup errors for the MYPS team.

## Delete one project from its row in Program Details (S01-TC004-P002)

- **Each project row in Program Details has a Delete button** (red trash icon) in a new Actions column. You no longer have to type the Project ID into Batch Delete to remove one project.
- It follows the Batch Delete rules. The **Delete Project** dialog first shows whether the project will be deleted permanently (still at the BP or RBP stage), deleted at the current stage (it can be restored from **Deleted projects**), or not deleted and why.
- Type DELETE and click **Yes, Delete Project** to confirm, or Cancel to stop.
- After a delete, the project table reloads on page 1.

## Generate Reports opens the Reports page for the program (S01-TC015-P001)

- **Actions → Generate Reports in Program Details now opens the Reports page** with Year, Program Stage and the program already selected. Pick the Report Type and Regional Office, then click Generate Report.
- The old report dialog inside Program Details is removed. Reports are generated only in the Reports module, where they are queued and downloaded when ready.
- A program is listed in Reports only at its current stage. Opened from an earlier stage, the program is not ticked, so choose its current stage.
- Generate Reports appears only for users who can open the Reports module.
- The RDIP and RBP Components reports from the old dialog are not in the Reports module yet.

## Changelogs button in the top bar

- **A Changelogs button sits at the top right of every page**, next to Search. It opens the list of changes in each release, newest first.
- A dot on the button marks changes you have not opened yet. It clears once you open the Changelogs.

## Code moved to GitHub, with automatic deployment

- Internal developer and deployment tooling only. Nothing visible changed.

## Dashboard header filters stay in place while the page loads (#470)

- **Program Type and Current Stages no longer move.** The header controls keep their position while the stage line, categories and fiscal years load, and after you pick a stage. Before, they slid sideways and up and down on every load.

## Funding Profile Amount reads a typed or pasted amount as pesos (#469)

- **A pasted or typed Amount keeps its value.** "1000000", "1,000,000" and "₱1,000,000.00" all read as ₱1,000,000.00. Before, the last two digits were read as centavos, so a pasted 1000000 became ₱10,000.00.
- The amount is formatted when you leave the field, not on every keystroke. Clicking into the field selects it, so a new amount replaces the old one.
- This applies to the Funding Profile on both the Project and Project Modification forms.

## Changing a component's type saves correctly (#468)

- **Changing a component's Component Type now saves.** For example, a Consultancy component changed to Civil Works becomes CW2 and keeps its year amounts. Before, saving failed with "Unable to locate Component 'CoS' for Cost Per Year." or the change was lost.
- The component's Major Items and work locations follow its new Component ID.
- Project Modification gets the same fix. Before, the edit was dropped and the component stayed as it was.

## Select Infrastructure finds Road Sections by Section ID (#466)

- **Search by Section ID or Road Name.** In Work Locations → Select Infrastructure, a Section ID such as S04516LZ now finds its road section. Before, only the Road Name matched.
- Bridges can be found by Bridge ID or Bridge Name.
- The search boxes say so: "Search by Section ID or Road Name..." and "Search by Bridge ID or Bridge Name...".

## Component Cost: clearer message when no year is entered (#465)

- "Please add at least one per-year cost." now reads "Component details are required for at least one year."
- The change applies to the Project, Project Modification and Lump Sum Component Cost dialogs.

## Batch action prompts name the program and its current stage (#459)

- **A batch action started from an older stage says so by name.** Batch Delete, Batch Restore, Allow Publishing and Restrict Publishing opened from a stage the program has moved past now show, for example, "Program 'GAA-Revisions 2026' has moved on to the GAA-R stage. Batch actions only work on a program's current stage: open it at GAA-R and try again." Before, the message said the Program ID did not exist.
- Nothing is changed when this message appears.
- Other program messages about stage, access or revisions name the program instead of its internal Program ID.
- The success message after deleting a program no longer falls back to the internal ID.

## Category and Thrust code tables filter by validity and status (#457)

- **New Validity and Status filters** sit next to Search on the Category and Thrust tables. Validity is All, Valid or Not Valid. Status is All, Active or Inactive.
- "Valid" means the row's end year has not passed. It is the same rule the Project Details Category and Sub-Category dropdowns use, so the filter shows what the project form offers.
- A Category with Valid Until 0 now reads "No expiry", like "Present" on the Thrust table.
- The User Manual explains that the project dropdowns follow validity only, and that Active or Inactive matters only once a row has expired.

## Agency and Thrust code tables are readable, and Thrust picks its Infra Type from a list (#456)

- **Agency and Thrust columns show their full text.** Long names, descriptions, programs and activities wrap instead of being cut off, so you no longer need to open Edit to read them.
- **Thrust's Infra Type is now a dropdown** of the active Infrastructure Types. A saved value that is not in the list is kept and marked "(not in list)", so editing never clears it.
- Add and edit rows on both tables use the same field height, and text fields stop at the length the database accepts.
- **Editing an Agency or Thrust keeps it Active.** Before, every edit made the row Inactive.

## User Manual: Infra Management section brought up to date (#455)

- User Manual only. The app is unchanged.
- Section 5.9 now describes Infra Management as it works today: RBIA rows show an RBIA badge instead of Edit and Delete, Classification lists only Primary, Secondary and Tertiary, and Road, Section and Bridge IDs are generated by the app.
- The Bridges column and dialog are described as Carriageway Width (m).

## Major Items of Work title no longer repeats (#454)

- The Major Items of Work section on the Project form no longer shows a second "Major Item of Work" title inside it. The Add Major Item button stays on the right.
- Project Modification gets the same change.
